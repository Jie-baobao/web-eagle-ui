🦅 Web Eagle 部署指南

基于 Eagle 资源库 JSON 索引的 Web 图片浏览器 — 只需 Nginx + PHP，无需数据库

1. 概述

1.1 架构说明

Web Eagle 是一个纯 PHP 程序，工作原理：

  1. 读取 Eagle 资源库中的 .eagle/tags.json 获取标签列表
  2. 读取 images/{UUID}/{UUID}.info.json 获取每张图片的标签关联
  3. 在前端实现多标签 AND 筛选 + 瀑布流浏览 + 灯箱查看

程序对 Eagle 资源库的所有访问均为只读，不会修改、创建或删除任何 Eagle 数据。

Web Eagle v4.1 新增 CSRF 保护、Rate Limit 防刷、XSS 防护等安全机制（详见第 11 章）。

1.2 不需要数据库

组件用途
Nginx 或 ApacheWeb 服务器
PHP 7.4+后端逻辑 + 图片代理
data/cache.json性能缓存（自动生成）
eagle_config.php配置文件（手动或 Web 设置）

1.3 功能特性

3.2 权限设置命令

# 假设 web_eagle 部署在 /var/www/web_eagle
cd /var/www/web_eagle

# 1. 设置所有者为 PHP 运行用户
chown -R www-data:www-data .

# 2. 程序文件只读
find . -type f -name "*.php" -exec chmod 644 {} \;
find . -type f -name "*.css" -exec chmod 644 {} \;
find . -type f -name "*.js" -exec chmod 644 {} \;
find . -type f -name ".htaccess" -exec chmod 644 {} \;

# 3. 目录可执行
find . -type d -exec chmod 755 {} \;

# 4. data/ 目录可写（缓存写入）
chmod 755 data/
touch data/cache.json 2>/dev/null
chmod 644 data/cache.json 2>/dev/null

# 5. 配置文件可读写
touch eagle_config.php 2>/dev/null
chmod 644 eagle_config.php 2>/dev/null

3.3 权限要点

🔒 权限原则：
程序文件（.php/.css/.js）→ 只读：防止 Web 漏洞被利用篡改程序
eagle_config.php → 可读写：setup.php 需要写入配置
data/cache.json → 可读写：API 需要写入缓存
Eagle 资源库 → 只读：程序绝不写入 Eagle 数据

4. 安全配置 ⭐

4.1 访问密码

外网部署时强烈建议设置密码，防止未授权访问。

  1. 访问 setup.php → 在"访问密码"区域设置密码
  2. 设置后，访问主页面需要先登录
  3. 修改密码：再次访问 setup.php 输入新密码
  4. 取消密码：清空密码字段并保存
⚠️ 密码安全：当前密码以明文保存在 eagle_config.php 中。此文件为 .php 后缀，无法通过 HTTP 下载。建议：
  • 使用不与其他服务相同的密码
  • 生产环境配合 HTTPS 使用

4.2 Eagle 数据只读保证

操作读取写入
tags.json✅❌
tagGroups.json✅❌
.info.json✅❌
图片文件✅（代理输出）❌
缩略图✅（代理输出）❌

程序唯一写入的文件：data/cache.json 和 eagle_config.php。

4.3 Nginx 安全规则

server {
    listen 8080;
    server_name _;
    root /var/www/web_eagle;
    index index.php;

    # 禁止访问配置文件
    location ~* eagle_config\.php$ {
        deny all;
    }

    # 禁止访问 data 目录
    location /data/ {
        deny all;
    }

    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
    }

    # 安全头
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-XSS-Protection "1; mode=block";

    # PHP 处理
    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    # 静态资源缓存
    location ~* \.(css|js|png|jpg|jpeg|gif|ico|svg|webp)$ {
        expires 7d;
    }
}

9. Nginx 性能优化 ⭐

目标：最低性能，最稳定运行。以下配置适用于飞牛 NAS、低配 VPS、树莓派等资源受限设备。

9.1 最低性能稳定运行配置

完整 Nginx 配置，整合安全规则 + 性能优化：

server {
    listen 8080;
    server_name _;
    root /var/www/web_eagle;
    index index.php;

    # ── 安全：禁止访问敏感文件 ──
    location ~* eagle_config\.php$ { deny all; }
    location /data/                { deny all; }
    location ~ /\.                 { deny all; }

    # ── 安全头 ──
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options SAMEORIGIN;

    # ── Gzip 压缩（只压缩文本，图片不需要）──
    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;
    gzip_comp_level 4;            # 4 是性能和压缩率的好平衡

    # ── PHP 处理 ──
    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;

        # 图片代理可能较大，增加超时
        fastcgi_read_timeout 60s;

        # 仅允许 POST 请求刷新缓存
        location ~* api\.php$ {
            limit_except GET POST { deny all; }
        }
    }

    # ── 静态资源：强缓存 + 不可变 ──
    # CSS/JS 很少改动，长期缓存
    location ~* \.(css|js)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;            # 静态资源不记日志，减少 IO
    }

    # 图片代理走 PHP，但客户端会缓存 7 天（api.php 已设 Cache-Control）
    # 这里匹配不到（因为走 api.php），无需额外处理
}

# ── 全局优化（放在 http {} 块内）──
# keepalive 减少连接建立开销
keepalive_timeout 65;
keepalive_requests 100;

# 减少 IO
access_log off;                    # 关闭访问日志（省 IO，稳定优先）
# 如需日志排查问题，改为：
# access_log /var/log/nginx/web_eagle.log combined buffer=32k flush=5m;

# 单个连接最大请求体（上传不需要，但保险起见）
client_max_body_size 1m;
💡 关键优化点：
• access_log off：关闭日志 = 减少 50% 磁盘 IO
• gzip_min_length 1024：小于 1KB 的文件不压缩，省 CPU
• gzip_comp_level 4：压缩级别 4 是性能/压缩最佳平衡点
• immutable：告诉浏览器资源不会变，不再发条件请求
• keepalive_timeout 65：复用 TCP 连接，减少握手开销

9.2 PHP-FPM 低资源配置

对于只有你一个人用的场景，PHP-FPM 不需要多进程：

; /etc/php/8.x/fpm/pool.d/www.conf（或宝塔对应的池配置）

; ── 进程管理：固定数量 ──
pm = static
pm.max_children = 2              ; 只有自己用，2 个进程足够

; ── 内存限制 ──
php_admin_value[memory_limit] = 256M

; ── 空闲进程回收 ──
pm.max_requests = 500            ; 处理 500 请求后重启进程，防内存泄漏

; ── 慢日志（排查卡顿用）──
request_slowlog_timeout = 5s
slowlog = /var/log/php-fpm-slow.log

; ── 关闭不必要的功能 ──
php_admin_value[expose_php] = off
💡 为什么 2 个进程够用？
你一个人用，同时最多 1 个请求在处理（浏览图片），另一个进程处理新进来的请求。
如果偶尔卡一下，改为 pm.max_children = 3 即可。
不建议超过 5 — 每个进程占 30-80MB 内存，5 个就是 150-400MB。

9.3 Nginx 直出图片（跳过 PHP）

默认方案图片走 PHP 代理（api.php?action=image_proxy），增加 PHP 负担。如果 Eagle 资源库在同一服务器，可以让 Nginx 直接提供图片文件：

server {
    # ... 其他配置见 9.1 ...

    # ── 缩略图直出（最大性能提升）──
    # URL: /eagle-thumb/{UUID}/{UUID}_thumbnail.png
    location /eagle-thumb/ {
        alias /mnt/nas/EagleLib/我的素材库/images/;
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;

        # 只允许内网 + ZeroTier 网段
        allow 192.168.0.0/16;
        allow 10.147.0.0/16;
        allow 127.0.0.1;
        deny all;

        # 只提供缩略图，防止遍历原图
        location ~ /eagle-thumb/[^/]+/[^/]+_thumbnail\.png$ {
            # OK
        }
        location ~ /eagle-thumb/ {
            deny all;              # 阻止非缩略图请求
        }
    }

    # ── 原图直出（可选，安全风险稍高）──
    # URL: /eagle-img/{UUID}/{UUID}.{ext}
    location /eagle-img/ {
        alias /mnt/nas/EagleLib/我的素材库/images/;
        expires 7d;
        add_header Cache-Control "public";
        access_log off;

        allow 192.168.0.0/16;
        allow 10.147.0.0/16;
        allow 127.0.0.1;
        deny all;
    }
}
⚠️ 启用直出需要修改前端代码：
在 app.js 中将图片 URL 从 api.php?action=image_proxy&id=XXX&type=thumbnail 改为 /eagle-thumb/{UUID}/{UUID}_thumbnail.png，原图同理。
当前版本默认使用 PHP 代理，开箱即用。如果你不确定，先不要改，PHP 代理对个人使用完全够用。

9.4 客户端缓存策略

资源缓存时间策略

10. 大规模数据性能设计 ⭐

本节介绍 Web Eagle 如何处理大规模图库（几千张图片）的性能问题。

10.1 设计思路

Web Eagle 的核心矛盾：用户需要跨页翻遍所有筛选结果，但服务器不能一次性把全部图片元数据发给前端。

解决方案：分层 API + 客户端分批加载

层数据触发时机体积
瀑布流当前页缩略图 + 元数据页面加载 + 滚动触发每页 N 张元数据
灯箱 ID 列表全部筛选结果的轻量元数据（无图片）首次开灯箱时（后台）几千个 ID，约几百 KB
图片代理实际二进制文件懒加载（缩略图+原图）按需加载

10.2 分层 API 设计

api.php?action=images       ← 分页图片列表（per_page 控制，默认 60）
api.php?action=image_ids    ← 灯箱专用：全部筛选结果的 ID + 轻量元数据
api.php?action=image_proxy  ← 图片二进制代理（缩略图 / 原图 / 下载）
api.php?action=tags         ← 标签列表（含预计算统计数）
api.php?action=refresh      ← 重建全量缓存（需 CSRF token）
api.php?action=csrf_token ← 获取 CSRF token（首次加载时自动调用） api.php?action=status ← 进程状态检查

10.3 设置项说明

设置项推荐值说明
每页图片数量30-60越小首次加载越快，建议远程访问设为 30
滚动加载方式无限滚动滚动到底自动加载下一页，不卡瀑布流
灯箱图片列表预加载全部开灯箱时后台加载全部 ID，跨页翻页无阻碍
缓存过期提醒1-7 天Eagle 新增图片后需手动刷新缓存才可见

10.4 缓存实时性

Web Eagle 在启动时扫描全部 .info.json 文件构建缓存，存放在 data/cache.json 中。

场景表现
首次访问自动构建缓存，5000 张约需 10-30 秒（取决于磁盘速度）
后续访问直接读 cache.json，无需再次扫描
Eagle 新增图片界面显示警告，点击右上角 🔄 重新构建缓存
Eagle 删除图片缓存不会自动清理（被动），下次刷新时重建
标签改名/删除同上，下次刷新缓存时同步
💡 缓存预计算优化：
构建缓存时一次性统计所有标签下的图片数量（tag_counts_precomputed），
后续请求 tags API 时直接读取，不再遍历图片列表。
5000 张图片的标签统计：从 O(n) 每次请求优化为 O(1)。

11. 安全说明

11.1 CSRF 保护

所有写操作（refresh 接口）均需要携带 CSRF token：

// 首次访问页面后，前端自动获取 token
GET /api.php?action=csrf_token
→ {"success":true,"data":{"token":"xxxxxxxxxxxx..."}}

// 写操作时在 HTTP 头中附带
POST /api.php?action=refresh
X-CSRF-Token: xxxxxxxxxxxx...

Token 存储在 Session 中，每次会话生成一次。攻击者无法跨域获取，因此无法伪造有效请求。

11.2 Rate Limit 防刷

refresh 接口有请求频率限制：同一 IP 最多 5 次 / 10 分钟。超出后返回 429 状态码，提示等待时间。

限制规则存储在 data/.rate_limit 文件中，10 分钟自动清理过期记录，无需手动管理。

11.3 XSS 防护

所有用户可见的文字内容（图片名称、标签名）均经过 HTML 转义后输出，杜绝 XSS 注入。

颜色值（标签颜色、调色板）经过格式校验，只允许合法 hex/rgb/rgba/hsl 值进入 CSS 属性。

图片 ID 使用严格 UUID 格式（8-4-4-4-12 小写十六进制）校验，无效 ID 返回 HTTP 400。

颜色值（标签颜色、调色板）经过格式校验，只允许合法 #fff / #ffffff / rgb() / rgba() / hsl() 值进入 CSS 属性。

11.4 生产环境安全建议

措施说明
启用 HTTPS强烈建议。外网访问时明文密码存在被截获风险，配合 HTTPS 加密传输。
设置访问密码setup.php 中设置密码后，所有 API 和页面均需认证。
Nginx 安全头已在响应中添加 X-Content-Type-Options: nosniff 和 X-Frame-Options: SAMEORIGIN。
Rate Limit刷新接口：同一 IP 最多 5 次 / 10 分钟，超限返回 429 并告知等待时间。
定期更新关注 Web Eagle 更新，及时修补潜在安全漏洞。
数据备份Eagle 资源库数据由 Eagle 管理，Web Eagle 不写入 Eagle 数据。

12. 常见问题

❓ 页面空白 / 500 错误

  • 检查 PHP 版本 ≥ 7.4
  • 检查 data/ 目录是否可写
  • 查看 PHP 错误日志：/var/log/php-fpm/error.log

❓ "未找到 .eagle 目录"

  • 确认输入的是 Eagle 资源库根目录，不是 Eagle 软件安装目录
  • 目录下应有 .eagle/ 和 images/ 子目录

❓ 图片加载失败

  • 检查 PHP 对图片目录是否有读取权限
  • SMB 挂载目录：确保 PHP 运行用户有权限
  • 宝塔 open_basedir 限制（见 5.5 节）

❓ 加载很慢

  • 首次加载需要扫描所有 .info.json 构建缓存
  • 后续使用缓存，速度正常
  • 远程访问：减小 per_page 为 30

❓ 忘记密码

  • 编辑 eagle_config.php，将 'password' 改为空字符串

❓ 灯箱翻不到其他页的图片

  • 首次打开灯箱时会后台加载全部筛选结果
  • 如果网络慢，可能需要等 1-2 秒才能跨页翻页

❓ 和 Eagle 同时使用会冲突吗

  • 不会。Web Eagle 只读取 JSON，不写入任何 Eagle 数据
  • Eagle 新增图片后点 🔄 刷新缓存
